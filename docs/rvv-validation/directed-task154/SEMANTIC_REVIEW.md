Task154 validates vmacc/vnmsac/vmadd/vnmsub, each vv/vx, using the prepared 40,232-case denominator. In assembler order vd,vs1/rs1,vs2, vmacc computes old_vd + vs1*vs2; vnmsac computes old_vd - vs1*vs2; vmadd computes vs2 + vs1*old_vd; vnmsub computes vs2 - vs1*old_vd. All arithmetic retains low SEW bits, with RV32 scalar sign extension at SEW64. Destination and source aliases read the captured complete prestate. Ten CSRs and s0, all 32 vector registers, masks, partial/zero VL, no-body/prestart preservation and policy allowed sets are checked. Reserved vstart >= VLMAX remains explicitly profile evidence, not ordinary ISA PASS. Sixteen reserved encoding declarations remain NOT_RUN.

The pilot and full snapshots contain the new MAC dispatch in the existing runner and auditor, including exact assembler operand order and instruction-word verification. Pinned Spike/pk executes the identical user ELF for zero start; pinned Sail executes the already-established initialization/termination adapter for nonzero start. Independent ISA predicates are a second check, never the only golden. The offline auditor verifies every source, target word and adapter and replays every packet; retained-cache decompression is outside this semantic audit. Per-target M1/M2 optimization admission is not established by enabling the switches.

Task154 adds a separately frozen `mac154qemu` 96-case/32-unit pilot: all eight forms at four pilot geometries, each with VLMAX−1, even mask and odd mask; recognizable 0x11 old destination and adapted scalar 0x55667788. Expected active values come exclusively from the independently pinned Spike/Sail packets and specification predicates. Old dst_vl/dst_even/dst_odd values are source history only and are never adopted as expected results.

While full MAC runs, widening integer development is isolated under `next-widen` and remote `widen-pilot`. Destination EEW=2*SEW and EMUL=2*LMUL; narrow sources use EEW=SEW/EMUL=LMUL; wv/wx source2 is already wide. Legal profile uses SEW8/16/32, LMUL up to m4 and all six VLENs. Legal narrow overlap requires source EMUL >=1 and the high end of the destination; wide source2 overlap has equal EEW. A register cannot supply two different source EEWs, so wv source-source conflict is declared reserved. Different-EEW overlap allows inactive/tail old or all-ones regardless of vta/vma, while prestart and no-body are preserved. Signed/unsigned extensions and signed-vs2/unsigned-vs1 vwmulsu are explicit, and all wide-result bytes are checked.
