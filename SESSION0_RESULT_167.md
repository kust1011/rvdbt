Old `Emit_vchunkfma` relies on one x86 fused instruction plus canonical NaN selection. x86 FMA can omit invalid for zero×infinity when a quiet-NaN addend supplies the NaN result. RMM instead uses the exact `softfp::op_fma` core, which already tests invalid product independently of the NaN addend. Task164's authoritative RISC-V/SoftFloat adjudication and its original independent references remain the semantic authority.

## Correction and interfaces

New internal [rv32_vector_fma_invalid.h](dbt/guest/rv32_vector_fma_invalid.h) states one rule: after stripping signs, one actual multiplicand is zero and the other infinity. The addend is irrelevant. Its scalar predicate is used by the ordinary host helper, fast residue and widening helper. Its SIMD overloads accrue host IE without changing rounding/other flags, and are used by inline chunk primitives and every 16/32/64-byte run kernel, including scalar broadcasts and unroll variants.

[Emit_vchunkfma](dbt/qmc/qcg/qemit.cpp) emits the same classification with integer SIMD shifts/comparisons before overwriting old vd, reduces invalid lane bits through the **actual active predicate**, and ORs guest NV. It retains the existing fused instruction and NaN canonicalization. The madd/msub forms classify old vd and source1/scalar; macc/msac classify source2 and source1/scalar. Product/addend sign placement is unchanged. Its temporary stack slot is balanced, scratch registers were already reserved, and shared active masks are preserved.

No existing production function signature, QIR node, CPUState/FPUState layout, runtime-stub interface, eligibility rule or FP bracket changed. Arithmetic remains fused and vectorized; this is exception classification rather than multiply/add decomposition or blanket scalarization. Masks, vstart and tails suppress the added NV exactly as they suppress arithmetic. Flag updates are sticky ORs, and scalar operands use the existing NaN unboxing.

Adjacent FP32→FP64 widening FMA is covered architecturally: its host helper applies the same rule before the fused operation; `RvvEmitTypedFWidenChunkGroup` widens operands exactly and maps all four accumulating signs into **the same corrected vchunkfma emitter**. No widening-family survey or new half-precision support was added.
