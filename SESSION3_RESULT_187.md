**Result:** the595-form evidence is real finite coverage, but does not close fault recovery or every instruction-semantic category. This audit establishes **no new default-QCG ISA bug**. ## Priorities for the advertised RV32GCV scope

1. **Preserve the unresolved precise-recovery obligation.** Correct PC, committed prefix, no newer commits, preserved older FP flags and a valid restart position must compose into correct resumed execution and eventual progress when the fault can be resolved. It is not a requirement to resolve permanent failures or exhaust all inputs. `ukernel.cpp:223–260`, `rv32_interp.cpp:51–67`, checked memory loops and native cold exits publish a plausible boundary; seeded nonzero-start tests establish suffix behavior. Their composition has not been demonstrated. P4-04 and equivalent handler-return/repair/same-PC retry remain service-blocked: **not retried, renamed, substituted or marked PASS**. Linux signal return is one integration route, not the definition of the ISA obligation; unhandled-fault termination alone does not demonstrate recoverability.
2. **Strengthen the specific denial predicate.** [focused.py](scripts/rvv/regression181/focused.py#L54) accepts nonzero exit plus any occurrence of “fault”, “segmentation” or “trap”. A wrong-target failure can pass. It establishes neither exact fault PC/raw/cause nor prefix/vstart. Keep the592 controls as failure controls; do not promote them to precise-trap proof. Future adjudication should join the exact ELF target and captured state using affected retained receipts, without re-auditing positive millions or launching guests. Existing detailed historical terminal fixtures remain separate evidence with their own build identities.
3. **Close a bounded inexact unordered-reduction category.** Task174 deliberately admits exact dyadic/tree-invariant subsets and restricted specials, excluding general inexact multi-active sums (`fpreduce174.py:78–105`). Production uses a legal sequential tree (`rv32_vector_lower.h:2264–2390,3214`). A small independent sequential-tree predicate can exercise rounding/cancellation, OF/UF/NX, sticky flags, masks and widening without requiring arbitrary Spike bit equality or all possible trees/inputs. This is missing evidence, not a confirmed reduction bug.

**Conditional production defect:** `--rvv-gather=1` is default-off (`config.h:4135`). `rv32_vector_gather.cpp:42–93` admits readable file mappings by permission alone, then executes unowned gather/memcpy accesses. A mapped page beyond backing-file EOF can SIGBUS; earlier chunks may already be visible while vstart remains0. For legal equal-EEW `vd==vs2`, earlier loaded data have overwritten their own index operands, so restarting at0 cannot generally reconstruct the original addresses. `ukernel.cpp:420–455` then reaches generic termination, not an owned precise boundary. This enabled path needs backing admission/checked fallback or real fault ownership. It is a source-confirmed defect, with no new executed witness and no established enablement in final181 arms. It does not invalidate the default-off evidence.

**Nonblocking diagnostic defect:** `ukernel.cpp:272` prints `NativeUnit` as `PredictedHelper`. The actual enum and native terminal assertions are correct; JSON provenance is not. Fix the formatter and add a bounded formatter assertion when Session0 integrates its work. This is not an ISA arithmetic defect.

## What is already covered, or legally variable

The [read-only compact review](docs/rvv-validation/obligations-task187/EVIDENCE_REVIEW.json) exactly joins627 navigation forms,595 required forms,595 final181 results and102 accepted index entries. All32 exclusions are ei64 indexed load/store forms: four ordering/direction families × NF1–8. **Section18.3 explicitly excludes EEW64 index support when XLEN32**; ELEN64 or RV32 alone is not sufficient justification. Data EEW64 and FP64 remain required. Base V requires scalar F/D, FP32/FP64 vector arithmetic/conversions and reductions; FP16/FP128 are not mandatory. No absent mandatory mnemonic family was found. Configuration/CSR coverage comes from147/148 and actual packet predicates, not the595 count.

Successful nonzero-start records exist for572 forms. The23 remaining forms are precisely the reductions, mask prefix/iota/count/first and compress classes with specified nonzero-start traps. Arithmetic may legally refuse positions it cannot produce for that same instruction/vtype; this permission cannot excuse refusing memory positions actually emitted by its fault path. The RUNNABLE macro's old comment claiming no resumable traps is stale, not a blanket architectural exemption.

FOF128 focused start/mask checks, later-fault trimming packets, and960 focused vill/whole checks already exist. Absolute element0 differs from the first resumed/active element. Legal early FOF shortening and spurious originally-active suffix updates are correctly allowed. Segment vstart counts segments; partial fields in the faulting segment are permitted. Whole-memory EVL depends on encoded EEW/NF, mask-memory EVL counts bytes, and whole moves use current SEW; ordinary VL is not their completion bound. Misaligned-access success versus a permitted misalignment trap is an implementation choice.

The apparent grouped-memory concern is **not a bug**: `rv32_vrun.cpp:1128–1137` cuts production runs at memory, and `qemit.cpp:1997–2009` forces multi-member memory through ordered checked helpers. Permission preflight is not treated as recovery ownership there.

Final buffer/winner checks cannot prove ordered device access history, non-idempotent access counts or cross-hart RVWMO behavior. Those are concrete platform-conditional memory obligations, not Linux signal ABI requirements. A claimed device environment needs a bounded access observer; this task adds no speculative MMIO suite. Privileged FS/VS ACT reference blockers, general Linux signals/syscalls, scalar/atomic fault compatibility, AOT/LLVM extensions and public packaging are separate scopes.
